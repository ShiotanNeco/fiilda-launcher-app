# FiiLDA Launcher

Galaxy Z Fold向けのAndroidホームアプリです。MacBookのキーボードとTouch Barから、黒い操作面・均一なキー・シアンの選択状態・横長のContext Barを再構成しています。

## できること

- HOMEアプリとして起動できるランチャー
- カバー／内側縦／内側横を画面幅・高さから自動判定
- インストール済みアプリの検出、アイコン表示、直接起動
- ウィジェットとお気に入りを同じホームフィールドへ配置
- お気に入りキー、検索欄付きの全アプリドロワー、ホーム上の長押し編集
- アプリ画面のアプリ長押しでお気に入りへ追加、ホーム画面の長押しメニューでサイズ変更・削除
- お気に入りの並びをSharedPreferencesへ保存し、ランチャー再起動後も保持
- アプリキーは正方形の1×1セルを基本とし、長押しメニューから横 1×2、縦 2×1、2×2、縦 3×1、縦 3×2セルを選べるほか、「自由に設定」で縦1〜6×横1〜4の好きな大きさに変更可能（ウィジェットも同じ）
- 横 1×2／縦 2×1は公開ショートカット1件を隣接セルに表示して直接起動し、2×2は最大3件を残りのセルに表示する（ショートカットがない場合は従来の拡大表示）
- 「ウィジェットを追加」の「Webリンク」で、好きなURL・名前・アイコン画像のタイルをホームに置ける。タップでブラウザが開き、画像がなければ名前の頭文字を表示（サイトへの通信はしない）。長押しメニューから編集・サイズ変更・削除
- お気に入りの長押しメニューで、タイルサイズとは独立して表示内容を「アプリのみ」「ショートカット付き」、または「通知ライブ」から選択可能（未設定はショートカット付き）
- 通知へのアクセスを許可すると、お気に入りアプリのホームタイルに未読件数を表示し、「通知ライブ」では最新通知をタイル内から開ける（履歴保存・インライン返信は非対応）
- ホームウィジェットはカバー画面・内側画面とも正方形の2×2セルで表示
- カバー画面ではお気に入りを全件、4列の小さな正方形キーで表示
- ホーム画面のアプリと内蔵ウィジェットを長押ししてドラッグし、挿入位置をプレビューしながら並べ替え、ドロップ時に順番を保存
- 時刻、日付、カレンダー、電池、天気、予定、メディア欄の表示
- 天気・週間天気予報タイルは、現在地（おおよその位置）の天気を[Open-Meteo](https://open-meteo.com/)から取得（APIキー不要、30分ごとに再取得、前回の結果を保存）
- 今日の予定タイルは、端末のカレンダーから今日の終日予定と、まだ終わっていない予定を表示。予定をタップで詳細、「+ 追加」で新規作成、「すべての予定を見る」でカレンダーアプリを開く
- メディア操作ウィジェットで、再生中のタイトル・アーティスト・アートワーク・進捗・前後移動・再生／一時停止を表示
- Androidのデフォルトホームアプリとして設定可能

## 時計・カレンダーの動的アイコン

ホーム、アプリ一覧、フォルダー内で、対応アプリの時計アイコンを現在時刻に、カレンダーアイコンを現在の日付に更新します。Google時計などの針情報と、Googleカレンダーなどの日別アイコン情報を利用します。秒針の情報がある時計は秒単位で更新し、表示されていない間は定期更新を止めます。通常のアプリアイコンやショートカット固有の画像は維持します。

Galaxy標準の時計・カレンダーには、Samsung端末の公開アイコン取得APIから画像を再取得する互換経路を用意しています。このAPIが動的な画像を返すかは端末のOne UI実装に依存するため、Galaxy実機での確認が必要です。取得できない場合や非対応のアプリでは通常のアイコンを表示します。

方式の参考：[AOSPのカレンダーアイコン処理](https://android.googlesource.com/platform/frameworks/libs/systemui/+/refs/heads/master/iconloaderlib/src/com/android/launcher3/icons/IconProvider.java)、[AOSPの時計アイコン処理](https://android.googlesource.com/platform/frameworks/libs/systemui/+/ed6c8179533957f846457fc5a00ded10c5a768d8/iconloaderlib/src/com/android/launcher3/icons/ClockDrawableWrapper.java)、[Androidの公開アイコン取得API](https://developer.android.com/reference/android/content/pm/LauncherActivityInfo#getIcon(int))。

## インストール直後の状態

- ホームには、時計・天気・今日の予定・カレンダー・バッテリー・メディアの6つのウィジェットを置きます。リマインダー・週間天気予報・フォトフレームは、ウィジェットの追加から置けます。
- アプリは、その端末で標準になっている電話・メッセージ・ブラウザ・カメラ・ギャラリー・メール・地図・カレンダーのアプリを最大8個置きます。見つかったアプリが4個より少ない場合は、アプリ一覧の上から足して4個にします。
- テーマはデフォルトです。
- 初めて開いたときは、スワイプでページをめくるチュートリアル（6ページ）を表示します。最後まで見るか「スキップ」を押すまで、開くたびに表示します。前のバージョンから更新した人には表示しません。設定の「使い方を見る」から、いつでもまた見られます。

## 表示言語

端末（またはアプリごと）の言語が日本語なら日本語、それ以外は英語で表示します。Android 13以降は「設定 ＞ システム ＞ 言語 ＞ アプリの言語」から、FiiLDA Launcherだけ言語を変えられます。言語を変えると、アプリを再起動しなくてもすぐに切り替わります。

日付は日本語では「10月5日 月曜日」、英語では「Mon, Oct 5」の形で表示します。令和の表示は日本語のときだけです。

画面の文字はコードの中で `tr("日本語", "English")` の形で書いています（`UiLanguage.kt`）。新しく文字を追加するときも、この形で日本語と英語を並べて書きます。

## システムの明暗設定に連動

設定の「テーマ」で、ライトモード用とダークモード用のテーマを別々に選べます。「システムの明暗設定に合わせる」をオンにすると、端末のモードに合わせて切り替わります。同じテーマを両方に指定することもできます。

システム連動と時間指定の「テーマローテーション」は、どちらかをオンにするともう一方がオフになります。システム連動をオフにした場合は、その時点のテーマを引き続き使います。ライト用・ダーク用の選択は残ります。

## ガラステーマ

設定の「テーマ」で「ガラス」を選ぶと、固定壁紙の上にクリアな角丸タイルを表示します。ホームとアプリ一覧の下部バーはスクロール内容の上に重なり、末尾の項目はバーの上までスクロールできます。内側横向きでは既存のナビゲーション構成を使います。

ショートカットの各マスは親のガラス面を透かし、枠線を表示しません。フォルダー内の枠・メディア操作ボタンも親のガラス面を透かし、輪郭と選択表示は白系に統一しています。文字下の黒背景とタイル外側の影は表示しません。アイコンや写真、アルバムアートの色は維持します。

設定の「ガラス」欄から壁紙画像を選択できます。画像は端末の壁紙とは別にFiiLDA内へ保存され、「標準に戻す」で内蔵背景に戻せます。他テーマに切り替えても画像は保持します。「透明効果を抑える」をオンにすると、読みやすい不透明な操作面になります。

同じ欄で、ぼかし（0〜48dp）・屈折の強さ（0〜32dp）・ガラスの濃さ（0〜100%）をプレビュー付きで調整できます。スライダー操作を終えると設定を保存し、再起動後も引き継ぎます。「ガラスの調整をリセット」はぼかし4dp・屈折8dp・濃さ0%へ戻し、壁紙や「透明効果を抑える」の選択は維持します。

Android 13以降は背景のぼかしと屈折、Android 12系はぼかし、Android 10〜11は透明色と輪郭による表示を使います。写真・動画・外部ウィジェットの内容自体は加工しません。動画や外部ウィジェットがナビゲーションバーの背後に入る場合、背景取得に対応しない描画領域は代替色で表示します。Appleの内部実装や自動的な形状融合を使用するものではありません。

## ビルド

Android Studioまたはターミナルで、プロジェクトルートから実行します。

```sh
JAVA_HOME='/Applications/Android Studio.app/Contents/jbr/Contents/Home' ./gradlew :app:assembleDebug --no-daemon
```

生成物：

`app/build/outputs/apk/debug/app-debug.apk`（`fiilda.buildRoot` 未設定時）

このMacではリポジトリがDocuments配下にあり、File Provider／iCloudの管理対象です。生成されるDEXなどのビルド出力が同期対象へ戻らないよう、必要な場合だけ、未追跡の `local.properties` に同期対象外の絶対パスを指定できます。配置例は次のとおりです（`<ユーザー名>` は自分のものに置き換えます）。

```properties
fiilda.buildRoot=/Users/<ユーザー名>/Library/Caches/FiiLDA/build-output
```

指定するとルートプロジェクトは `build-output/root`、アプリは `build-output/app` 配下へ出力されます。APKの実際の位置は、次で確認できます。

```sh
find ~/Library/Caches/FiiLDA/build-output -path '*/outputs/apk/debug/app-debug.apk' -print
```

出力先は `:app:properties` の `buildDir` でも確認できます。

```sh
JAVA_HOME='/Applications/Android Studio.app/Contents/jbr/Contents/Home' ./gradlew :app:properties --no-daemon | rg '^buildDir:'
```

`fiilda.buildRoot` を指定しない場合は、従来どおり `app/build` 配下へ出力されます。プロジェクトディレクトリ自身、その配下、またはプロジェクトを含むパスは安全のため指定できません。

## 配布用（リリース）ビルド

配布用APKは、リポジトリの外に置いた署名鍵で署名します。未追跡の `local.properties` に、署名情報を書いたファイルの場所を指定します。

```properties
fiilda.releaseSigning=/Users/<ユーザー名>/.fiilda/release-signing.properties
```

指定したファイルには次の4項目を書きます。鍵ファイルとこのファイルは、Gitにも同期フォルダにも入れず、別の場所へバックアップしてください。鍵をなくすと、同じアプリとして更新版を配れなくなります。

```properties
storeFile=/Users/<ユーザー名>/.fiilda/fiilda-release.jks
storePassword=...
keyAlias=fiilda
keyPassword=...
```

```sh
JAVA_HOME='/Applications/Android Studio.app/Contents/jbr/Contents/Home' ./gradlew :app:assembleRelease --no-daemon
```

`fiilda.releaseSigning` を指定しない場合、リリースビルドは署名なしで出力され、そのままではインストールできません。

## 計測用（profiling）ビルド

開発用（デバッグ）ビルドはコードが最適化されないため、配布版より大幅に遅く動きます。動作の重さを確かめるときは、配布版と同じ速さで動き、開発用と同じ鍵で署名される計測用ビルドを使います。開発用ビルドの上に、データを消さずに上書きできます。

```sh
JAVA_HOME='/Applications/Android Studio.app/Contents/jbr/Contents/Home' ./gradlew :app:assembleProfiling --no-daemon
```

計測用ビルドだけに、テーマを外から切り替える仕組みがあります（`adb shell am broadcast -n com.fiilda.launcher/.ProfilingThemeReceiver --es theme glass`）。`dumpsys gfxinfo` と simpleperf で計測できます。

## 実機へのインストール

USBデバッグを有効にしたGalaxy Z Foldへ接続し、次を実行します。

`fiilda.buildRoot` を設定した場合は、上で確認した外部APKのパスを使います。

```sh
adb install -r ~/Library/Caches/FiiLDA/build-output/app/outputs/apk/debug/app-debug.apk
```

`fiilda.buildRoot` 未設定時は、従来の標準パスを使います。

```sh
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

インストール後、Androidの「設定 > アプリ > デフォルトのアプリ > ホームアプリ」からFiiLDA Launcherをデフォルトのホームアプリに設定してください。

メディア操作ウィジェットを使う場合は、「設定 > 通知 > 通知へのアクセス > FiiLDA Launcher」を許可してください。許可後、端末で再生中のMediaSessionをホームフィールドへ反映します。

## ウィジェットのデザイン

メディア・フォトフレーム以外の内蔵ウィジェット（時計、天気、週間天気予報、今日の予定、カレンダー、バッテリー、リマインダー）は、テーマごとのデザイン言語で描画します。タイルの形と面の色は各テーマのものをそのまま使い、内側の見出し・数字・メーター・「今日」の印だけを切り替えます。

| テーマ | 内側の表現 |
| --- | --- |
| デフォルト | キーボードのキーのような均一なセル、細い線、現在の状態だけシアン |
| Classic | アイボリーと淡い青のブロック、赤は「今日」「現在」の1色だけ |
| 窓 | フラットなMetroタイル、細い大きな数字、名前は左下 |
| マテリアル | トーナルな丸いアイコン台、ピル形のメーター、円形の「今日」、プライマリ色 |
| ガラス | 半透明の白と白文字、不透明な内側ブロックなし |

メディア操作ウィジェットも同じ言語でボタンを描きます。再生／一時停止を最も大きくし、デフォルトはシアンのキー、Classicは赤いキー、窓は円形の輪郭ボタン、マテリアルはプライマリ色の角丸ボタン、ガラスは白い円です。アルバムアートは全面を暗くせず、タイトルとボタンの帯だけに陰影を付けます（窓はグラデーションを使わず、帯状の単色）。1行サイズではアートのサムネイル・曲名・ボタンを横に並べます。窓テーマでは、メディア操作タイルの色がアルバムアートの主な色（アプリタイルと同じ抽出方法）に変わり、曲が変わると約0.9秒のフェードで切り替わります。白い文字が読めるよう、明るい色はコントラスト比5:1以上になるまで暗くします。アートがないときは標準の青に戻ります。

各ウィジェットは 1×2・1×4（1行）、2×2、2×4 の大きさに合わせて内容を変えます。「自由に設定」でほかの大きさ（最大 縦6×横4）にもできますが、内容は1行・横長・それ以外のうち合う配置で表示します。時計は24時間のセルと次のアラーム、バッテリーは実際の残量・充電状態・温度・状態・満充電までの時間、カレンダーは前後の月の日付を含む月表示（1行では今週）を表示します。リマインダーには、まだ連携するデータ元がありません。

デバッグビルドでは、全テーマ・全サイズを並べて確認できます。

```sh
adb shell am start -n com.fiilda.launcher/.WidgetGalleryProbeActivity --es theme windows8 --es size square
```

`theme` は `default`／`classic`／`windows8`／`material`／`glass`、`size` は `square`（2×2と1×2）／`wide`（2×4）／`strip`（1×4）／`media`（メディア操作の各サイズと状態）です。`--ei from 3` で先頭のウィジェットを飛ばせます。`--es size media --ez cycle true` では、最初のタイルのアートが3秒ごとに切り替わり、色のフェードを確認できます。

## 天気と予定

天気タイルと週間天気予報タイルは、初回に「位置情報を許可」を押すと、おおよその位置（`ACCESS_COARSE_LOCATION`）を使えるようになります。位置は小数第2位（約1km）に丸めてからOpen-Meteoへ送ります。地名は端末のGeocoderで取得します。取得は前回から30分以上経ったときだけで、ホームに戻るたびに通信することはありません。オフラインのときは前回の結果を表示します。タイルをタップすると、すぐに再取得します。

今日の予定タイルは、初回に「カレンダーへのアクセスを許可」を押すと`READ_CALENDAR`を使います。表示するのは、表示が有効なカレンダーの予定のうち、辞退していないものだけです。ホームが表示されている間は、カレンダーの変更（同期を含む）を監視して表示を更新します。

## 現段階の扱い

アプリ検出とアプリ起動、再生中メディアのMediaSession連携、通知ライブタイルの最小構成（現在通知の受信・表示・起動）は実装済みです。天気と今日の予定は実データです。バッテリーも実データです。リマインダーは表示のみで、データ元は未実装です。通知履歴やインライン返信、各サービスのバックグラウンド更新は次工程で追加します。
